## Descripción del proceso
Inicialicé el repositorio local con `git init` y creé la estructura del proyecto junto a la documentación inicial. Realicé varios commits informativos a medida que avanzaba. Posteriormente, vinculé el repositorio local con GitHub mediante `git remote add origin` y subí la rama principal. Creé una issue para proponer mejoras en la documentación y abrí una nueva rama con `git switch -c` para realizar los cambios. Finalmente, publiqué la rama, creé la Pull Request en GitHub, la integré a la rama principal y me bajé los cambios actualizados a mi equipo local con `git pull`.

## Dificultades encontradas
Durante el proceso se presentó una confusión al intentar subir la rama secundaria a GitHub, la cual solucioné utilizando `git push -u origin mejora-readme`. Todos los comandos funcionaron sin mayores inconvenientes.

## Reflexión final
El uso de Git y GitHub me permitió entender la importancia de llevar un historial de cambios ordenado y utilizar ramas para probar modificaciones sin poner en riesgo la versión estable del proyecto.
